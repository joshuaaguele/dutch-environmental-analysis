# Dutch municipal environmental analysis — candidate code release

Author: Joshua Oseijgbe Aguele

This draft contains the baseline R workflow for an independent study of Dutch municipal environmental indicators. It contains the baseline and drought/flood sensitivity scripts for the code release for “Municipal environmental exposure profiles for climate adaptation in the Netherlands”, submitted to Theoretical and Applied Climatology. The preprint was submitted for Research Square screening on 3 October 2026; no public DOI is confirmed here. The related heat-exposure manuscript was submitted to Applied Spatial Analysis and Policy. Neither manuscript is described here as accepted.

## Scope
The baseline script imports and documents neighbourhood data, constructs municipal indicators, and performs exploratory PCA, clustering, bootstrap stability, heat regression and spatial modelling. These methods support distinct manuscript questions; they are not all analyses from the TAC paper.

## Run the baseline
1. Open Dutch_Environmental_Analysis.Rproj in RStudio.
2. Install dependencies with `install.packages(c("tidyverse", "readxl", "janitor", "sf", "spdep", "spatialreg", "fpc"))`.
3. Obtain the Klimaateffectatlas Buurtdashboard source workbook from the provider: https://www.klimaateffectatlas.nl/ . Use the exact study version (9 March 2026), not an unchecked replacement download.
4. Place it at `data_raw/Downloadbuurtdashboard_maa26-2.xlsx`.
5. From the project root, in a fresh R session, run `source("scripts/04_full_environmental_analysis.R")`.
6. Inspect generated tables and outputs. Save session information and compare results with the submitted manuscripts.

The source workbook is absent. The code checks workbook dimensions and may need compatible system libraries for spatial packages. Spatial analyses may retrieve municipal boundaries from the network. This draft has not been executed end to end in this environment; archived outputs are not evidence of successful reproduction.

## Run sensitivity analyses after the baseline
From the project root, run:

```r
source("scripts/05_drought_sensitivity.R")
source("scripts/06_flood_sensitivity.R")
writeLines(capture.output(sessionInfo()), "outputs/sensitivity/release_session_info.txt")
```

Both scripts require `tables/municipality_environmental_indicators.csv` generated by script 04. Script 05 also reads the baseline script to display clustering settings. Script 06 requires exactly one Buurtdashboard XLSX workbook in data_raw. Run each in a fresh R session after generating the inputs, so success does not depend on workspace objects.

Script 05 saves log-drought cluster profiles, membership comparisons, the excluded municipality and `drought_sensitivity_summary.csv`. Script 06 saves municipal denominator comparisons, sample counts, `flood_cluster_summary.csv`, fitted model objects and session information under outputs/sensitivity.

The drought filename was corrected from the uploaded `05_drought_sensitivty(1).R`; its bytes are unchanged. Only explanatory comments changed in script 06; numerical statements are unchanged. Historical flood_missing/flood_coverage field names are retained, but refer to a conditional denominator and the population-weighted share of retained neighbourhoods, not missing-data correction or data completeness.

## Interpretation
Analyses are exploratory and describe environmental exposure profiles; they do not establish causal effects or comprehensive vulnerability. Flood percentages refer to neighbourhood area. A population-weighted mean of those percentages is not the percentage of residents exposed. The provider clarified that blanks in the specified coastal/fluvial flood-depth fields indicate no inundation in that category; this does not justify replacing missing values in unrelated variables with zero.

See docs/RELEASE_REVIEW.md before making the repository public.
